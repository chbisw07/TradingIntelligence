## 4. Architecture reconciliation choices beyond those findings

| Brief issue | Decision / reason |
|---|---|
| Platform versus family | FF hosts arbitrary admitted instruments; FM/LFDE stays advanced, optional and scientifically falsifiable |
| Recursive notation | Typed finite DAG/config, not a new DSL or arbitrary string evaluator |
| Raw conceptual nested voting | Requires explicit type/calibration/class conversion; the notation itself does not authorize combining incompatible results |
| Calibration location | Fit / apply / evaluate owners separated; child and parent calibration are different artifacts and scopes |
| Role versus lifecycle | Independent assignments and evidence/approval histories; SHADOW role and lifecycle explained without one giant enum |
| “N=1” miniature | Singleton valid for mechanics; comparative miniature normally has two primitives, base rate and logistic, with at most one approved PRIMARY |
| Shared truth/ledger | One journal plus immutable joined ledger versions; late labels create later projections, not edited forecasts |
| Comparison added after issue | Evaluation manifest links old run IDs later; never require mutable future comparison IDs inside the original forecast |
| Best component | Validation-selected comparator separated from best-on-test oracle; no look-ahead selection policy |
| Component removal | New declared experiment/composition with calibration/refit rules; not undeclared missing-child renormalization |
| Shared-node budget | Execute once per identical run/input identity, charge once plus actual retries; no double parent/child totals |
| Regime/dispersion signals | Report context, support and disagreements; no hardwired router/abstention rule invented now |
| FF-4 / FF-5 sequence | Optional LLM and FM tracks can branch from the qualified miniature; an LLM is not required for numeric FM research |
| Simple system first | FF-0–FF-2 deliver complete control/evaluation/calibration/replay; later sophistication may be rejected |
| Existing A7 | Preserve exact current documents; specify later §/slice integration map and enum/projection migration review |
| Thesis strategy | Choose A: new FF system/platform thesis, retain FM/LFDE research handbook; no rename/regeneration now |
| Papers | Paper 1/2 remain FM/LFDE papers evaluated inside FF; no generic-framework novelty claim or papers written |
